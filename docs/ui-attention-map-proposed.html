    What could still be missed

    These are hypotheses about looking behavior, including shortcuts and omissions. Heat is manually chosen; looking at a control does not prove understanding. Task grouping, approval context and permission hierarchy are implemented; the diagram remains illustrative and does not reproduce every screen or state.

    Scope and assumptions

    This is a design proposal, not a capture of the shipping interface. It reduces the central greeting, groups the task prompt with its examples, expands permission language, prioritizes the exact write and destination, strengthens work status, and surfaces pending decisions when returning.

    Scenarios assume a sighted, English-reading desktop user with the sidebar expanded. Prior product experience and task intent can change the route. Each alternate path is conditional, not a measured user segment. Mobile and assistive-technology routes need separate validation.

    Regions, heat intensity and optional numbered paths are manual predictions. Counts vary by activity; a person may jump directly to an action, revisit a region, ignore it or leave the app. Scroll controls show paused checkpoints, not continuous eye tracking.
